# Shulker Box Sort

适用于 Minecraft Java 版 **26.2** 的 Fabric **服务端模组**。把背包中的普通原色潜影盒视为一张虚拟大表，在服务端直接完成物品合并、默认分类与名称排序、分盒和空盒堆叠，无需逐盒打开容器或等待每组物品同步。

**客户端未安装本模组时，玩家也可以直接使用 `/shulkersort`，无需 OP，只整理自己的背包。** 客户端安装后可额外使用背包中的整理按钮。无需 Item Scroller、MaLiLib 或 Quick Shulker。

## 使用方法

1. 在服务端安装本模组和 Fabric API，进入游戏后输入 **`/shulkersort`**；普通玩家无需 OP，也不必安装客户端模组。
2. 如果客户端也安装了本模组，可以改为点击原版背包面板内部右上角的 14×14 `⇅` 小按钮。
3. 查看完成提示中的整理盒数、腾空盒数、剩余非空盒数和空盒堆叠释放的格数。

整理在服务端一次调用内完成，不禁用玩家背包、移动或切换视角。执行时请先放下光标物品并关闭其他容器；两次请求至少间隔 500 ms。

整理范围与规则：

- 只整理未染色、未命名、无特殊用途组件、数量为 1 的普通原版潜影盒。
- 彩色盒、命名盒、特殊盒和堆叠的非空盒会被跳过。
- 单一物品且容量完全满的盒子会锁定，不参与重排。
- 处理主背包和快捷栏 36 格，不处理盔甲、副手或背包外的箱子；不需要空中转槽，背包全满也能整理。
- 空盒只按服务端实际堆叠上限及完整组件一致的规则合并，支持 `MAX_STACK_SIZE` 和 Carpet 的 `shulkerBoxStackSize`。
- **未开启潜影盒堆叠也会完成物品整理与排序**，空盒保持分开，完成后显示黄色警告：未开启潜影盒堆叠，空潜影盒未进行堆叠。

## 关键问题与实现思路

### 1. 多个潜影盒不是一个真实容器

服务端把符合条件的盒内内容组成一张虚拟大表，直接计算并写入目标布局。无需在客户端打开、隐藏、反复同步每个盒子。

### 2. 物品相同不只取决于物品 ID

合并键由“物品 ID + 完整数据组件”组成。附魔、耐久、名称、容器内容等组件不同的物品严格分离；不可堆叠物品也不会错误合并。

### 3. 排序后不能按背包顺序绑定盒子

目标页面通过最大权重二分匹配分配给物理潜影盒：优先保留盒内已有的相同物品数量，其次保留同槽同数量堆，再确定性打破平局。这样靠后盒子持有大量排序前段物品时，可以直接承接前段页面，减少跨盒搬运。

### 4. 大宗物品与分页边界

六组及以上的物品优先分页。完整27组先形成同类满盒，余量再与其他内容组合；单一物品且完全满的盒子直接锁定。只有“不拆分就必须额外增加非空盒”时，较小的大宗组才会跨页。

### 5. 不满组不能逐格向后冒泡

物品超过一盒且靠前存在不满组时，从尾部来源直接补满，不让不满组沿27格逐次后移。物品不超过一盒且合并不能减少占用格数时，保持首次出现顺序，不为把不满组移动到末格而做无效搬运。

### 6. 服务端整理与物品安全

先在背包副本上生成完整结果，逐项验证物品数量、完整组件和盒壳组件守恒；提交前核对全部 36 格快照。操作在服务端主线程内完成，不跨 tick 等待。写入失败时尝试恢复原快照并核验，最后使用原版背包同步通知客户端。

### 7. 内置默认排序与合堆收尾

默认规则移植自 Item Scroller 26.2-0.32.1：钻石/下界合金工具优先，普通物品按建筑、染色、自然、功能、红石、工具、战斗、食物、材料、刷怪蛋、管理员、其他分类排列，同分类按名称排序；收纳袋和潜影盒按默认规则后置。全局合堆后直接分页写回，空位同时参与规划，无需再调用外部模组逐盒收尾。

名称使用服务端语言（通常为英文），不受客户端语言或 Item Scroller 配置影响；组件相同的物品堆仍保持稳定顺序，大宗分页和同类满盒锁定继续生效。分类在服务端启动和数据包重载后准备。

## 安全边界

- 光标有物品、打开其他容器、死亡、旁观或请求过于频繁时拒绝执行。
- 结果校验或提交前快照不一致时不应用目标布局；提交写入异常时尝试恢复原库存。
- 只操作请求者自己的背包，不接受客户端提供的物品、数量或其他玩家目标，也不要求 OP。
- 未开启空盒堆叠不会导致中止，不主动丢弃物品。
- 网络回复丢失时服务端可能已完成整理，客户端会提示检查背包，不会错误宣称已经回滚。

当前代码已通过 48 项自动测试和无 Item Scroller 等前置的专用服务端加载检查，尚未完成真实整合包的联机验收。

## 已知问题

旧 2.x 客户端版在锁定物品栏期间，与 Tweakeroo 或 Ommc 的自动装备鞘翅可能冲突，导致胸甲或鞘翅异常；旧版可打开聊天栏中止后手动穿脱恢复。此说明保留给仍使用旧版的玩家。当前 3.x 服务端版不再使用客户端锁定物品栏流程。

只修改特定容器点击行为的第三方空盒堆叠模组可能需要额外适配；服务端无法识别可堆叠规则时保留空盒并在完成后提示。只在客户端追加的自定义创造分类可能归入“其他”。

## 从源码构建

需要 Java 25：

```powershell
.\gradlew.bat clean build
```

Linux/macOS：

```bash
./gradlew clean build
```

成品位于 `build/libs/`。规划器测试覆盖组件隔离、合堆守恒、稳定排序、大宗分页、乱序匹配、置换环和不满组直供等场景。
